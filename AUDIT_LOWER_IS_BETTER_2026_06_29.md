# lower_is_better Metric-Direction Audit (2026-06-29)

> Generated by an 86-agent find→verify→synthesize workflow over 72 files (core engine,
> c01–c24, s01–s13, n01–n13, analysis scripts, importance/utils). Triggered by a
> molecular "hybrid hurts" result that turned out to be a read-side sign bug (caco2 RMSE
> negative delta = improvement). See `memory/project_metric_direction_signbug.md`.

## 1. Executive Summary

Hunted for sites that decide on a per-dataset model-performance metric score without
consulting the dataset's metric direction (`lower_is_better`). KIRBy uses `rmse`/`mae`
(lower-is-better) for molecular regression but `r2`/`spearman`/`ci`/`auc`/`f1_weighted`/
`mcc` (higher-is-better) everywhere else — so the **same score field means opposite
things across datasets**.

**Result: 6 confirmed real bugs across 4 files. 0 HIGH, 2 MEDIUM, 4 LOW.**
No bug currently corrupts a committed result on the antibody/clf datasets run today, but
every one is direction-unsafe and would invert on molecular RMSE/MAE datasets.

**The core engine and all selection paths are CLEAN** — `find_best_hybrid`, `hybrid`,
`screen`, `_shared`, `c02`, and all helpers correctly use `min if lower_is_better else max`.
The bugs are all in **reporting/diagnostic/offline-analysis code**, not in any path that
selects the rep/config/model that becomes a committed result.

**Single systemic root cause:** metric direction is **not persisted into the result JSON**,
so analysis/reporting code re-guesses it — and the guesses are ad-hoc. Fix at the root by
persisting `metric_name` + `lower_is_better` into every result JSON (§5).

## 5. Canonical Correct Idiom

Derive direction once, from the registry — never re-guess from the metric-name string:

```python
from tests.experiments._shared import get_domain_metric   # -> (metric_name, metric_fn, lower_is_better)
metric_name, metric_fn, lower_is_better = get_domain_metric(data)
# backed by _resolve_dataset_metric -> DATASET_REGISTRY in tests/experiments/dataset_policy.py
```

```python
# Selection — branch on direction (never bare max / reverse=True):
best = min(candidates, key=score) if lower_is_better else max(candidates, key=score)
# pandas: df.nsmallest(k,'score') if lower_is_better else df.nlargest(k,'score')
# sort:   rows.sort(key=score, reverse=not lower_is_better)

# Delta / "improvement" — flip the sign for lower-better:
delta = (base - score) if lower_is_better else (score - base)   # positive == improvement, always

# Generalization gap (c09): gap = (val - train) if lower_is_better else (train - val)  # +ve == overfit
# Robustness slope (c10):   robustness = -nds if lower_is_better else nds              # higher == more robust
```

**Root-cause recommendation — PERSIST the direction.** Every one of these sites had to
re-derive direction (and got it wrong) because the result JSON does not record it. Write
`metric_name` and `lower_is_better` into every result JSON (most experiments already thread
both through `make_structured_output` — just pass the real `lower_is_better`, never a
hardcoded literal). Then analysis/aggregation reads the persisted field, and cross-dataset
aggregates can normalize direction before mixing RMSE datasets with R²/spearman/auc.
