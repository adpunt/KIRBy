### `tests/experiments/annitia/refuse_holdout.py` — DEFERRED
- Line 186: `scores[v] = (rh + rd) / 2` averages two Spearman correlations (variant val-prediction vs cross-variant mean, computed separately for hep and death endpoints).
- This is NOT a C-index aggregation; it's a "stability" heuristic used to pick the top-K most central variants (line 188-191).
- Strictly speaking, if you intend this stability-score to track LB-relevance, it should be `0.7 * rh + 0.3 * rd`. But the current code is using it as a symmetric "is this variant central in BOTH endpoints" filter.
- **Risk:** changing this WILL change which variants get selected, which changes `sub_master_holdout_pick.csv`. Since this submission CSV may be a candidate for the leaderboard, do not silently overwrite.
- **Proposed one-line fix (deferred):** `scores[v] = 0.7 * rh + 0.3 * rd` (line 186).

## NEEDS USER APPROVAL (deferred)

1. **`tests/experiments/annitia/refuse_holdout.py:186`** — `scores[v] = (rh + rd) / 2` (Spearman stability average). If treated as a proxy for "LB-relevance", should be `0.7 * rh + 0.3 * rd`. Changing it WILL alter which variants land in the top-K and thus the contents of `sub_master_holdout_pick.csv` (a candidate submission). User should decide whether to:
   - (a) leave as symmetric stability filter (current),
   - (b) flip to LB-weighted (`0.7*rh + 0.3*rd`) and re-run accepting the new CSV.

2. **`tests/experiments/annitia/oof_to_leaderboard.py` structural issue** — most submissions share the same consensus OOF proxy, so `oof_lb` is near-constant (≈0.857) and the calibration fit is degenerate (negative Spearman, residual std 0.011 dominated by LB noise). The 0.7/0.3 fix is correct but doesn't unbreak the calibration — that requires per-recipe OOF reconstruction. Out of scope for this audit.
