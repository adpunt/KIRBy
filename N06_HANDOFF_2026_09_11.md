## What "done" means

**The end state of this work is n06 finalised and ready to submit to the cluster.** Not
"changes applied" — submittable. Nothing here is finished while n06 still has to be run by hand.

Two probes decide scope before any of it is built: the estimator-distinctness run and the
ChEMBL hERG pull (Task B). Both are local, both take minutes, and both report counts back to the
owner. **Report those counts before building on them.** If the ChEMBL probe comes back thin,
ChEMBL does not become a provider and Task B stops there — that is a result, not a failure.

Everything else runs locally first. No change goes to the cluster on the strength of reading it.

### The checklist. n06 is ready when every line is true.

1. **It is dispatched.** n06 is in `SINGLE_DATASET_EXPERIMENTS` in `noise_helpers.py`, the
   comment excluding it is gone, and `python tests/experiments/run_dataset.py noise <dataset>`
   runs it without naming it explicitly.
2. **`bash tests/slurm_scripts/submit_all_datasets.sh noise --dry-run` lists the jobs it would
   submit, and n06 is in them.** Dry run only. Nothing is submitted from this work without the
   owner saying so.
3. **Both existing smokes pass, updated for the new shape.** `_smoke_n06.py` (synthetic data
   with known disagreement, asserts the correlation recovers it) and `_smoke_n06_e2e.py` (a real
   `bindingdb_kd` run at a small budget). A smoke that was edited to pass is not a passing smoke.
4. **A real run, on real data, scoped to minutes, on each provider that survived its probe.**
   BindingDB and the cross-curator provider at minimum. Reading the code is not evidence it
   works — the last audit of this kind found four defects by reading and four more on the first
   real run.
5. **Every provider reports its counts in the result file**, and every dataset where a provider
   found nothing writes a skip with the count it found. No silent empty results.
6. **The result file carries `metric` and `task_type`.** Result files missing these are dropped
   by the result database with no error, and a whole job has been lost to it before.
7. **No path into a scratch directory.** Three complexity files were dead for weeks because they
   imported from `/private/tmp`. Checkpoints and outputs go under `tests/results/`.
8. **Nothing under `src/` changed without saying so explicitly.** The loader changes in Task B
   do touch `src/kirby/datasets/`; call that out rather than folding it in.
9. **Committed to `similarity-metrics-study`.** The server runs that branch. A plain `git pull`
   on `main` gets none of this.
10. **A short note back to the owner**: what was run locally, what the probes returned, what is
    still unverified, and what the cluster job would cost.

### What is explicitly not done as part of this

Submitting the job. Sizing the SLURM request from a guess rather than a measured local run.
Deciding, on the probe results alone, to cut a provider, an estimator or a dataset — probes
produce counts and counts go back to the owner.

## What n06 is for, and why it is being rebuilt rather than deleted

Every other noise experiment injects the noise. n11 corrupts training labels at six levels and
asks which detector recovers the most; n13 does the same across ten noise shapes. Both answer
"do our methods find the noise we put there".

n06 is the only file in the suite where the noise is real. BindingDB holds the same drug
measured against the same protein by different labs, and the spread of their pKd values is
disagreement nobody chose. Measured on the cached copy at
`/Volumes/seagate/KIRBy/dta/bindingdb_kd_meta.csv` + `bindingdb_kd_processed.npz`:

- 52,272 rows, 46,090 distinct (drug, protein) pairs
- 3,494 pairs measured more than once, covering 9,676 rows
- across those 3,494 pairs, the labs disagree by a median of 0.560 log units and a mean of 0.983
- the whole dataset's label spread is 1.395, so the typical two-lab disagreement is 40% of it
- 1,148 pairs disagree by more than a full log unit

Davis and KIBA were checked the same way and have **zero** repeated pairs — they are
deduplicated matrices. There is no second drug-target dataset to extend to. Two other routes
exist and both are in scope here: the Lhasa hERG data (Change 2) and a ChEMBL re-query (Task B).

The problem is not the question. The problem is that the file answers a smaller one: it ranks
ten noise estimators by correlation and reports the largest number in the table, on one dataset,
run by hand.

## Change 1 — n06 takes a list of ground-truth sources, not one hardcoded dataset

**Do this first. Every other change assumes it.**

**What is wrong.** n06 is pinned to `bindingdb_kd` and is deliberately kept out of the runner.
`noise_helpers.py` says so in a comment above `SINGLE_DATASET_EXPERIMENTS`: *"N06 (BindingDB
ground-truth) is dataset-specific — not in the per-dataset list. Run separately."* So it is
hand-run, on one dataset, and nothing schedules it.

That has to go. n06 is about to have at least two ground-truth sources with different label
types, and it must handle more arriving later without a new branch each time.

**What to do.**

Give n06 a **ground-truth provider** interface. A provider answers two things for a dataset:
which molecules form a repeat group, and how much the repeats disagree. Everything downstream —
which estimators, which spaces, which correlation — is the same regardless of which provider
supplied the ground truth.

Three providers to start:

| provider | groups molecules by | disagreement is | statistic |
|---|---|---|---|
| drug-target repeats | same drug and same protein | standard deviation of the group's pKd | Spearman |
| cross-curator | same InChIKey in two curated sets | the two calls differ, yes or no | AUROC |
| ChEMBL multi-document | same compound and target in different papers | standard deviation of the group's pIC50 | Spearman |

The hook for the first one already exists and is already generic: `build_replicate_groups`
accepts an explicit `data['replicate_groups']` array and only falls back to drug and protein ids
when none is given. Any loader that supplies that array works with no change to n06.

**Put n06 into the per-dataset dispatch.** Add it to `SINGLE_DATASET_EXPERIMENTS` and delete the
comment that excludes it. On a dataset where no provider finds a repeat structure, n06 writes a
skip with the reason and the count it found — it does not raise, and it does not silently write
an empty result. A dataset with no repeats is a fact worth recording; Davis and KIBA both look
like candidates until you count.

**A provider must count before it runs.** Report how many groups it found and how many molecules
those cover, and refuse below a floor — a correlation over 40 groups is not a result. Put the
floor in one named constant, not inline.

## Change 2 — the Lhasa hERG data goes in alongside BindingDB

**Standing reason, from the owner:** it is her supervisor's company's data and it should be
analysed to the fullest extent. This is not an optional extension.

**What exists.** `tests/experiments/federated/lhasa_herg_loader.py` holds
`dedup_across_silos`, which removes a molecule from later silos when its InChIKey has already
been seen, keeps the first silo's copy, and **never checks whether the two silos gave it the
same label**. fed03's three silos are `chembl`, `lhasa_train` and `lhasa_test`, so a dropped
molecule is the same compound curated independently by ChEMBL and by Lhasa, each with its own
hERG call. That is disagreement between two organisations, and it is discarded with no record.

**Measured on this machine**, with the Lhasa files at `~/repos/dphil/data/`:

- Lhasa holds 12,155 molecules across `hERG_lhasa_training.pkl` and `hERG_lhasa_test.pkl`
- those two files have **zero** InChIKey overlap with each other — a clean split, no leakage
- 336 of the 12,155 also appear in the cached ChEMBL hERG Ki set (1,415 molecules)
- binarising ChEMBL's pKi at 5.0, the two organisations give **opposite calls on 51 of 336**,
  15.2%

**Two things about the labels that change the statistic.**

Lhasa's label is binary — active or inactive — so a molecule's ground truth is not a magnitude.
With exactly two curators per molecule it is a flip: they agreed, or they did not. So the
statistic is **AUROC of the estimator's noise score against the agree/disagree flag**, not a
Spearman against a standard deviation. Do not force it into the Spearman path.

The disagreement rate depends on where ChEMBL's continuous pKi is cut. At 5.0 it is 15.2%, at
6.0 it is 33.6%, at 7.0 it is 70.5%. Most of that movement is the threshold, not the curators.
Pick one threshold, state it in the result file, and report the rate at the other two beside it
so a reader can see the sensitivity. Do not pick the threshold that gives the nicest number.

**Fix `dedup_across_silos` regardless of anything else here.** For every molecule it drops,
record which silos held it and whether their labels agreed. The InChIKey match is already being
computed; nobody is looking at the labels behind it. Return that alongside `dedup_stats`.

**Where the result belongs.** The estimator ranking goes into n06, through the cross-curator
provider, so it can be rank-correlated against the BindingDB ranking the same way. The
federated reading of it — when two organisations disagree about a compound, do the noise
estimators flag it — belongs in fed03 and should be written there too.

**Honest limits to carry into any write-up.** 336 shared molecules against BindingDB's 3,494
groups. A binary flag against a continuous spread. A chosen threshold against no threshold at
all. This is a supporting check, not a replacement for BindingDB. Task B is what could make it
larger.

## Change 3 — n06 stops producing a ranking and starts checking one

**What is wrong.** n06 currently computes 10 estimators × 2 feature spaces = about 20 Spearman
correlations and writes the largest to `results.summary.best_estimator` /
`.best_space` / `.best_correlation`. That is the maximum of 20 draws and is biased upward by an
amount nobody has measured. It is also a twelfth opinion about which detector is best, when n11
and n13 already rank detectors on injected noise at far greater depth.

**What to do.** Make n06's headline the transfer question: *does the estimator ordering measured
under injected noise survive on real measurement error?*

- Read n11's and n13's stored rankings of the estimators.
- Compute n06's ordering of the same estimators on the replicate ground truth.
- Report the rank correlation between the two orderings, per feature space, plus the full
  per-estimator table.
- Delete `best_estimator`, `best_space` and `best_correlation`. Nothing should report a maximum
  over the table.

**Estimator set.** n06 must run the set n11 runs, or the orderings cannot be compared.
`ESTIMATORS_SCREENING` in n06 currently includes `leave_one_out`, which n11 does not run, and
omits `hybrid`, which n11 does. Take the list from n11's `BASE_ESTIMATORS` and intersect it with
what n06 can actually fit.

**Names.** `src/kirby/utils/noise_estimation.py` holds one `ESTIMATOR_REGISTRY` with 17 keys for
13 distinct classes. `distance_weighted` and `distance_weighted_residual` are the same class; so
are `cross_val` / `cross_val_residual` and `ensemble` / `ensemble_disagreement`, each marked
`# alias` in that file. n06 uses the long spellings and n11 the short ones, so the two result
files do not join on name even though they ran the same code. Normalise through the registry —
resolve every name to its class before joining, do not hand-write a mapping.

## Change 4 — fit the estimator inside each fold, and never glue the fold blocks together

**What is wrong.** `_oof_hybrid_space` builds the hybrid feature space one fold at a time, which
is right — no molecule helps choose its own features. It then stacks the five folds' blocks into
one matrix, checking only that all five kept the same *number* of features, not the same
features. Column 7 holds a different feature depending on which fold the row came from. The
noise estimator is then fitted once on that mixed matrix.

**What to do.** For each fold, fit the estimator on that fold's training rows in that fold's own
space, score that fold's held-out rows in the same space, and pool the per-molecule scores. Costs
5 estimator fits per estimator instead of 1, on four-fifths of the molecules each.

`build_fold_hybrid` already returns the training side; n06 discards it. Keep it.

Delete the width check and the whole-rows fallback that triggers when the folds disagree — once
nothing is stacked, disagreeing widths are no longer a problem to fall back from.

## Change 5 — one row per replicate group in the correlation

**What is wrong.** `compute_replicate_stds` takes each group's standard deviation and broadcasts
it to every member. On BindingDB that means the Spearman runs over 9,676 rows carrying 3,494
distinct ground-truth values, and the `n_ground_truth` written beside the correlation is the row
count. The independent sample is overstated by about three times.

**What to do.** Reduce to one point per replicate group before correlating: the group's
ground-truth standard deviation against the group's mean (or median) estimator score. Write
`n_replicate_groups` beside the correlation, not the row count.

## Change 6 — actually compute the second question

**What is wrong.** n06's second question is whether an estimator agrees better in the hybrid
space than in a single representation. The file writes both correlations and never subtracts
them. The entry in `EXPERIMENTS_FINALIZED.md` marks this ⛔ *never computed*.

**What to do.** Write the per-estimator difference, and name which representation the comparator
was — `results.comparator_space` already exists for this and is no longer the fixed string
`concat`.

---

## Change 7 — the gaussian process subsample is abandoned, measurably

**What is wrong.** `GP_MAX` is 1000. The subsample keeps every replicate row first, then tops up
with non-replicate rows to reach 1000. When there are already more replicate rows than 1000 the
`else` branch sets `sub_idx = rep_idx` and the cap is silently dropped.

On BindingDB there are 9,676 replicate rows. `gaussian_process` is O(n³), so that branch hands it
roughly 900 times the work the cap was written to prevent.

**What to do.** Subsample *within* the replicate rows when they exceed the cap — sample whole
groups, not individual rows, so no group is left with one member and a meaningless standard
deviation. Record how many groups were dropped.

---

## Change 8 — keep the per-row output

**What is wrong.** Per-row noise scores and per-row replicate standard deviations are discarded.
Any re-analysis means a full re-run, and a full run is 6 hybrid builds at 262 to 336 seconds each
— 26 to 34 minutes before a single estimator is fitted.

**What to do.** Write both arrays to the result file, alongside the group ids.

## Change 9 — the pool subset

Already decided, not yet implemented: n06's hybrid pool subset includes the similarity hybrids —
the ones whose features were chosen by distance rather than by prediction. Whether a
distance-built space detects real measurement error better than a prediction-built one is exactly
the kind of question the similarity hybrids exist to answer.

## Do first, before any of the above: which estimators are distinct

13 distinct estimators exist. Nobody has established how many measure different things.

Score every estimator on one dataset in one feature space, correlate their per-row scores against
each other, print the matrix. One fit per estimator on one dataset — minutes locally. If four of
them agree at 0.98 they are one method occupying four slots in n06, n11 and n13 alike.

This prunes the list for all three files at once and tells you which estimators are
neighbour-based, which are the ones that actually exercise a distance.

Do not cut anything on the result without the owner's sign-off — a measured redundancy is a
reason to ask, not a reason to delete.

## Task B — pull hERG from ChEMBL locally and see whether it works in this context

**Do this before anything is built on ChEMBL, and report the counts back to the owner before
sizing a larger pull.**

hERG is the right first target for three reasons. It is `CHEMBL240`, one of the most-measured
targets in ChEMBL, so if multi-paper repeats exist anywhere they exist here. `herg` and
`herg_ki` are both already datasets in this repository. And Lhasa's data is hERG, so whatever
comes back also feeds Change 2 — a proper ChEMBL hERG pull is the one thing that could take the
cross-curator overlap well past the 336 molecules measured today.

`chembl_webresource_client` 0.10.9 is installed on this machine.

**The query.** One target, not the top 200:

```python
from chembl_webresource_client.new_client import new_client
acts = new_client.activity.filter(
    target_chembl_id='CHEMBL240',
    standard_type='IC50', standard_units='nM', standard_relation='=',
).only(['canonical_smiles', 'standard_value', 'target_chembl_id',
        'document_chembl_id', 'assay_chembl_id', 'standard_type'])
```

Standardise the SMILES and compute InChIKeys the way `chembl_bioactivity` already does, then
group by InChIKey and report, without averaging anything:

- how many raw records came back, and how many survived SMILES standardisation
- how many compounds have more than one record
- of those, how many have more than one **document** id — this is the number that matters; a
  compound with 4 records from 1 paper is one measurement listed four times and carries no
  disagreement
- how many have more than one **assay** id
- the spread of pIC50 within the multi-document groups: median, mean, 90th percentile, and how
  many exceed 1 log unit — the same four numbers BindingDB was measured on, so the two are
  directly comparable
- how many of those compounds also appear in Lhasa's 12,155 InChIKeys

**The gate.** If the multi-document group count comes back thin, or the spreads are near zero,
the full 200-target pull is not worth running and ChEMBL does not become a provider. Say so and
stop. If it comes back strong, the numbers above size the larger pull and tell you whether to
group within assay or across assays.

**Run it locally.** It is one target over the web API, minutes not hours, and the answer decides
whether any of the loader changes below get made at all.

## Task B, continued — the loader changes, only if the probe passes

**Where the repeats go today.** `src/kirby/datasets/chembl_bioactivity.py` queries the ChEMBL web
API live, then at its deduplication step groups by `(inchikey, target_chembl_id)` and replaces
each group with the mean pIC50, printing how many measurements it removed. Only the
post-average frame is written to disk. There is no raw file to recover from — the disagreement
is discarded before anything is cached.

**Three changes make it recoverable.**

1. **Cache the raw frame too**, before the groupby. One extra `to_csv`.
2. **Keep the spread at the groupby.** It currently aggregates `smiles: first, pActivity: mean`.
   Add `std` and `count` on `pActivity`. Those two columns are exactly the ground truth n06 wants
   and they cost nothing.
3. **Ask ChEMBL for the provenance fields.** The query's `.only([...])` requests
   `canonical_smiles`, `standard_value` and `target_chembl_id` — nothing that says where a
   measurement came from. Add `document_chembl_id` and `assay_chembl_id` to the same call; it is
   the same request with three more fields.

Point 3 is not optional. Without a document id you cannot tell two independent papers from the
same measurement listed twice. A duplicated record has zero disagreement, and enough of them
drag the ground truth toward zero and make every estimator look worse than it is.

**One caveat to state in any write-up.** ChEMBL's IC50 depends on assay conditions — cell line,
substrate concentration, incubation time. Two papers reporting different IC50 values for the same
compound and target may both be right about different assays. That is still noise from the
model's point of view, because the label it trains on is ambiguous, but it is a weaker claim than
BindingDB's. Kd is a property of the binding pair; IC50 is a property of the experiment. Filter
by `assay_chembl_id` where you can, and say which you did.

**Two ChEMBL-derived sets that will not work.**

`chembl_qsar` downloads a pre-made per-target CSV that already holds one row per compound. The
repeats were removed by whoever built that benchmark file.

`herg_ki` loads a cached `chembl_herg_ki.csv` that is two columns, SMILES and pKi, 1,415 rows.
Averaged upstream of this repository.
