# rep-pool-not-in-result-db-identity

**title:** The result database never records which representations the search ran over, so a 3-rep run and a 10-rep run share every row

**area:** The search cache key (_make_search_meta / _search_cache_path / _search_checkpoint_path) and the result_db row identity (IDENTITY_COLS + CONFIG_COLS) + tests/experiments/similarity/ (s01–s13,  + tests/experiments/opig_*.py (all eleven) + tests/experiments/opig_*.py (all eleven) + tests/experiments/federated/ (fed01-fed0

**class:** A-wrong-answer

**severity as reported:** large

**location:** src/kirby/result_cache.py:46-67 (IDENTITY_COLS), src/kirby/result_cache.py:93-96 (rep_pool is DATA_COLS), src/kirby/find_best_hybrid.py:7485-7505 (result_db_identity), src/kirby/find_best_hybrid.py:7519 (rep_pool recorded as data), src/kirby/find_best_hybrid.py:6117-6130 (rows reused wholesale)

## evidence as reported
result_cache.py:46-67 IDENTITY_COLS = ('tier','labels_hash','groups_hash','n_folds','seed','cv_splitter_id','metric','task_type','objective') -- no rep_names, no rep_shapes. result_cache.py:93-96: "Recorded on every row as plain data (NOT part of the key): the rep pool the search ran over... Never matched on for reuse -- the pool is fixed by tier+config, so it never needs to be a key." find_best_hybrid.py:7519 `result_db_rep_pool = repr(tuple(_esm.get('rep_names') or ()))` and result_cache.py:96 `DATA_COLS = ('rep_pool',)`. The search meta DOES key on it -- find_best_hybrid.py:601-603 'rep_names' and 'rep_shapes' -- but expected_search_meta is now only ever used as checkpoint_meta (find_best_hybrid.py:7737); the searches/*.pkl is never loaded or written, so that guard protects nothing durable.

## fix as proposed
Move rep_pool out of DATA_COLS and into IDENTITY_COLS, and build it from the same _esm['rep_shapes'] rather than 'rep_names' so a width change (feature_blacklist, screen_threshold) separates too. That widens the primary key, so every result_db/*.db has to be deleted -- same discipline as the 2026-09-04 metric/task_type and 2026-09-10 objective additions. Note the premise in the result_cache.py:93-96 comment is false as written: tier is caller-chosen free text and _shared.run_nested_cv defaults it to 'general' for every dataset.
